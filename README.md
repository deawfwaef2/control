# 机械病毒：赤巢协议

> 求救信号，比事故早了七分钟。十七天后，她仍站在门后。

**M8 · NEON CUT 0.7** — 日系机娘、不可逆感染、双阵营等额行动的离线棋类战役。实际可玩的持续迭代原型。

## 下载后直接玩

- **[下载离线 ZIP](https://github.com/deawfwaef2/control/raw/refs/heads/main/机械病毒-可直接游玩.zip)**：解压，双击 `开始游戏.html`。
- **[下载单文件 HTML](https://github.com/deawfwaef2/control/raw/refs/heads/main/开始游戏.html)**：保存后用现代浏览器打开。
- `index.html` 和 `开始游戏.html` 是同一份完整游戏。约 **11 MiB**，内嵌 **30 张美术、2 首完整循环 BGM**。

无需安装、服务器、CDN、字体下载或联网。浏览器可自动保存，也可在系统菜单导出/导入 JSON。沙盒预览若禁止存储或声音，请下载后独立打开。

### 建议先看、先听

1. 首页选 **赤巢意识**，可直接看到朔夜的新斜侧立绘、发光眼睛与胸前装置。
2. **人物 → 控制态预览 → 点击肖像**，查看十二人的完整状态图；预览不会改变真实阵营。
3. 点击 **接入作战**，首次真实点击后启用音乐与音效。右上角 **♫** 或演出中的 **♫ 混音** 可分别开关音乐/音效、调音量；旁边的扬声器是总静音。
4. 旧档可以继续，但这轮规则变化较大。想看完整新开场、使用一致的新规则，请先导出旧档，再开新战役。

## 当前核心规则

**只有赤巢的赤蛛棋子吃到敌方机娘，才会永久夺控。其他所有棋子吃子就是击杀。无法解救。**

- 赤蛛寄生：进入目标格，机娘转红并移至赤蛛原格；二者本阶段锁定，新载体在下个己方阶段才可行动。
- 普通机娘、受控机娘、哨卫、哨塔、载毒信使、运输匣：攻击敌人一律击杀，不会感染或反向转换阵营。
- 赤蛛吃到非机娘装置也直接摧毁。
- **没有拆卸解救、净化、治疗复活或击破控制器后归队。** 受控者被普通攻击吃掉会死亡。
- 击杀、感染、阵营、经验、环境损毁、物品与选择跨章保留。合法撤离不是治疗，也不会改变阵营。
- 每单位每阶段最多一次，**没有玩家阶段总行动次数上限**；玩家用 N 次，敌方得到 N 次额度。
- 阶段切换与演出不恢复行动；增援本阶段锁定。阶段内撤回是战术推演回滚，不是游戏内的解救能力。

旧档原有的阵营和死亡历史不被擅自重写；载入后所有新动作按上述规则执行，并显示迁移提示。

## 日系立绘与受控效果

本轮新生成 **9 张日系赛璐璐斜侧/回身立绘**：零音、璃雀、朔夜、珀弦、白栖、苍澜、绯律、霁川、祈雾。绛刃、雾棘、弥砂保留已有斜侧底图，不把这三张冒称为完整重绘。

新版 N–6 是重新生成的发光红色机械核心、黑银底座与短金属固定夹，胸前占比更明显。十二人的受控态统一为 **胸甲装置 + 红色发光眼睛**；采用干净立绘、生成装置、透视贴合和眼部光效合成，不声称额外生成了十二张完整重绘。璃雀与祈雾回身较大，装置按真实侧向透视展示部分轮廓，没有把正面装置贴在背上。

生成原图不依赖原作截图或人物素材打包。旧版装置曾参考 RE5 胸前控制器的比例，本轮在此方向上重新设计发光外观；不是官方联动资产。

- 完整成品素材：`assets/*.webp`。
- 贴合坐标与眼部光源：`art-neon.json`。
- 可重做十二人控制态：`python3 neon_art.py`（需要 Pillow、NumPy）。
- 正常构建只用已提交 WebP，不依赖临时原始 PNG。

## 五章、每路线十六段目标

保留双阀轮末稳定、密钥运输、轨道锁、双终端校验、核心破锁与十二轮广播防守。

为避免新规则卡死旧任务：
- 接舷取证可截获信使数据，也可在 D8 固守读取原始授时头，不要求解救璃雀。
- 守护者镜像库由任意己方单位守住同步座，不要求朔夜归队或存活。
- 赤巢仍须感染弥砂、保有朔夜；误杀/失去必要载体会明确判败。
- 镜像电源的保留或隔离改变敌我部署、生产间隔与在线证据完整性，**不改变朔夜阵营、不复活死者**。
- 终局停产协议阻止下一例感染，不会治愈已经受控的人。

具体任务见 [CAMPAIGN.md](CAMPAIGN.md)。六份证据、双线开场、条件终幕与分支说明见含剧透的 [STORY.md](STORY.md)。人物死亡或离场后的台词明确使用留存记录，不让另一名角色冒名代说。

## 构建与验证

```sh
python3 build_game.py
```

构建仅需 Python 3 和 Node.js（语法检查），原子更新两个 HTML、可玩 ZIP 和上级独立 HTML。无运行时 npm 依赖。

源码顺序：`data.js` → `cast.js` → `engine.js` → `ui.js` → `presentation.js` → `campaign.js` → `ensemble.js` → `screenplay-data.js` → `screenplay.js` → `protocol.js` → `audio.js`。后两层是当前不可逆规则界面/分支与声音实现；不要根据未使用的旧对白恢复双向解救规则。

检查依赖可放 `/tmp`，避免占持久工作区：

```sh
npm install --prefix /tmp/control-qa --cache /tmp/control-npm-cache playwright@1.58.2
PLAYWRIGHT_BROWSERS_PATH=/tmp/control-browsers /tmp/control-qa/node_modules/.bin/playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=/tmp/control-browsers node qa/check.cjs
```

Linux 如缺浏览器系统库，需安装 Playwright 提示的依赖。测试会分批关闭/重启浏览器，避免多个大图、音频页面在小内存环境里同时占用资源。

**M8：85/85 项专项检查通过**，报告为 `qa/m8-report.json`。包括规则、AI、十二种走法、旧档迁移、永久状态、目标可达性、演出恢复、移动端真实按钮、两首音乐解码与实际输出 RMS、总/分轨静音、真实移动/击杀/寄生音效、设置保存、发光眼睛与装置透明边缘。本次记录的页面异常和外部网络请求均为 0。

包哈希、ZIP CRC、音频及三个 HTML 的一致性见 `qa/package-report.json`。

这些是固定局面和界面专项检查，**不是完整人工通关、玩家平衡测试或电影品质认证**。演出使用生成静帧、镜头动画和音乐，没有专业配音或完整人物动画。

每次编程先读根 [handoff.md](handoff.md) 并 fetch 真实远端；交接只追加，不覆盖，不强推。每阶段先保存可玩 HTML，再检查、提交、推送；整个工作区低于 128 MB，绝不提交凭据。发布状态以真实 Git 结果为准。
