# 机械病毒：赤巢协议

> 求救信号，比事故早了七分钟。十七天后，她仍站在门后。

**M6 · ECHO CUT 0.5** — 原创成年机娘、双阵营、等额行动的离线棋类战役。实际可玩、持续迭代的原型，不是商业完成版。

## 下载后直接玩

- **[下载离线游戏 ZIP](https://github.com/deawfwaef2/control/raw/refs/heads/main/机械病毒-可直接游玩.zip)**：解压，双击 `开始游戏.html`。
- **[下载单文件 HTML](https://github.com/deawfwaef2/control/raw/refs/heads/main/开始游戏.html)**：保存后用现代浏览器打开。
- 根目录 `index.html`、`开始游戏.html` 是相同的完整游戏，可直接打开或静态托管。

无需安装、服务器、CDN、外部字体或联网。30 张美术内嵌在约 4.43 MiB 的 HTML 中。浏览器自动保存，系统菜单可导出/导入 JSON；沙盒预览禁止存储时，请下载独立打开。

### 先看这三处

1. 首页 **人物 → 控制态预览 → 点击肖像**：查看十二人的完整立绘，单独切换自主态/控制态。纯美术预览不会改动战役。
2. 选择阵营，**接入作战**：看片头。可手动下一镜、上一镜、自动放映；声音默认关闭。
3. 战役内 **证据**：查看已收集的原件与对白记录。线索跟随真实目标推进解锁，跳过演出不会漏拿；尚未取得的线索与后续解释不会提前公开。

旧六人存档可以迁移。想从头观看重写片头，请先导出旧档，再开始新战役；读取旧档不会强迫重播已经经过的章节。

## 这轮实际改变了什么

### 控制器，而不是长腿大蜘蛛

参考 RE5 胸前控制装置的紧凑比例，重新生成本项目的 **N–6**：低轮廓半透明红色卵形药仓、黑银底座、三对短固定爪，贴附闭合胸骨装甲。没有打包原作截图、标志或人物。

十二人均有自主态和控制态美术。璃雀、弥砂、朔夜的控制态是完整生成编辑；其余九人的控制态由干净底图与新生成装置合成，不宣称全部完整重绘。

### 十二人，十二种实际走法

新增珀弦、白栖、苍澜、绯律、霁川、祈雾。全体角色为 25—33 岁成年人，有独立立绘、走法、同步强化、出场职责、阵营及损毁状态，不是图鉴里的空名单。

| 原阵容 | 新阵容 |
|---|---|
| 零音 · 限距后 | 珀弦 · 同向连跳巡骑 |
| 绛刃 · 直线突击 | 白栖 · 直走斜吃 |
| 璃雀 · 骑士跳 | 苍澜 · 王步近防 |
| 雾棘 · 斜线穿行 | 绯律 · 隔子炮 |
| 弥砂 · 工程支援 | 霁川 · 3×2 斑马跳 |
| 朔夜 · 镜像机动 | 祈雾 · 折线狮鹫 |

按正常章节顺序，出场阵容为 **4 → 8 → 10 → 12 → 12**；先桥后病区时，登场顺序相应变化。不会开局把十二人挤满棋盘。

### 用证据与责任推动剧情

重写双线五章开场、所有段落转折和条件终幕。六份证据连接时间差、控制器、撤药记录、空货舱、签名与地面制造端。不同角色掌握不同部分的信息；发现责任者不等于自动替她免责。

新增证据档案和对白记录；保留并重写证人去向分支，加入终局发送内容选择。死亡或已撤离角色的台词明确标为记录，不借另一名角色的脸代说。**含剧透的创作交接见 [STORY.md](STORY.md)。**

### 演出与作战分开

信箱式画幅、人物近景、反向构图、文件插镜、控制器特写、逐字字幕、可选程序音效；任务说明放在独立任务卡中。支持上一镜、自动放映、跳过、减少动态效果。打开任务卡/模态窗口或切出页面时，自动放映暂停。

这是生成静帧与浏览器镜头动画的演出，**没有专业配音、完整角色动画或预录电影**，也不以“大师级”作为已验证结论。

## 保留的玩法底线

- 双阵营可玩，五章，每路线 **16 个作战段落**；赤巢定位为更高难度。
- 每个单位每阶段最多一次，**没有玩家阶段总行动次数上限**；你花 N 次，敌方获得 N 次额度。
- 吃子夺控换位，刚转换的单位锁定；阵营、经验、损毁、撤离、物品与选择跨章继承。
- 轮末守点、工程操作、轨道锁、镜像同步、核心破锁与十二轮广播防守。
- 100%—175% 棋子放大、立绘/总览切换、手机棋盘横向滑动。
- 演出不恢复行动、不复活角色、不替代关卡目标。

具体目标与继承规则见 [CAMPAIGN.md](CAMPAIGN.md)。

## 构建与验证

```sh
python3 build_game.py
```

需要 Python 3 和 Node.js（打包前语法检查），没有运行时 npm 依赖。构建原子更新两个 HTML、ZIP，以及上级工作区的独立 HTML。

源码顺序：`data.js` → `cast.js` → `engine.js` → `ui.js` → `presentation.js` → `campaign.js` → `ensemble.js` → `screenplay-data.js` → `screenplay.js`。样式为 `style.css`、`cinematic.css`、`screenplay.css`。当前剧本以最后两个 JS 为准；旧基础层对白保留作历史实现，但已被新演出入口覆盖。

离线专项检查需 Playwright/Chromium；依赖可装在 `/tmp`，不占持久工作区：

```sh
npm install --prefix /tmp/control-qa --cache /tmp/control-npm-cache playwright@1.58.2
PLAYWRIGHT_BROWSERS_PATH=/tmp/control-browsers /tmp/control-qa/node_modules/.bin/playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=/tmp/control-browsers node qa/check.cjs
```

Linux 环境如缺少浏览器系统库，需另安装 Playwright 提示的系统依赖。

## 协作纪律

每次编程前读根目录 [handoff.md](handoff.md) 并 fetch 真实远端；交接只追加，不覆盖，不强推。每阶段先保存可玩 HTML，再检查、提交和推送。整个工作区低于 128 MB；不提交访问令牌。推送是否完成以真实 Git 结果为准，不把本地构建当作已经发布。
